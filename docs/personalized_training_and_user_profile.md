# MindDuet：针对性训练与动态用户画像设计

## 1. 项目真正要解决的问题

MindDuet 最重要的功能不是让 AI 回答几个象棋问题，而是让系统长期理解一个用户，根据真实学习证据持续调整训练内容，并验证训练是否真的有效。

```text
观察用户
→ 建立有证据的动态画像
→ 提出可验证的诊断假设
→ 安排针对性训练
→ 检查训练是否有效
→ 修正画像和训练策略
```

AI 的优势在于处理大量历史数据、发现跨时间模式、快速检索相似错误和组合不同训练方法。教师或教练的优势是理解教学目标、动机、情绪和真实情境。系统的目标不是让 AI 取代教师，而是让 AI 扩大教师能够观察和服务的范围。

## 2. 当前训练功能与不足

当前象棋系统已经能够：

- 从用户历史中提取局面损失超过 30 的真实错误局面；
- 把错误局面保存到 `training_positions`；
- 记录训练答案、用时和正确性；
- 根据掌握度安排立即、1 天、3 天、7 天、14 天、30 天的间隔复习。

这还是个性化训练的初级版本，主要不足是：

- 只知道“损失了多少分”，还不能稳定判断“为什么犯错”；
- 训练主要是原局面重做；
- 只接受皮卡鱼第一推荐着，判分过于严格；
- DeepSeek 生成的训练建议只是文字，尚未自动转化为交互式习题；
- 还没有根据最近多盘的重复错误制定阶段训练计划；
- 还不能验证训练后的进步是否迁移到真实对局。

## 3. 完整个性化训练闭环

```text
收集用户对局
→ 识别重复错误模式
→ 建立能力画像
→ AI 制定阶段训练计划
→ 从真实错局生成习题
→ 皮卡鱼验证题目和答案
→ 用户完成练习
→ 更新掌握度
→ 检验真实对局中的同类错误是否减少
```

系统不能只告诉用户“这一步错了”，还要回答：

1. 这是什么类型的错误？
2. 它是否在不同对局中重复出现？
3. 可能对应什么思考习惯？
4. 应该进行什么训练？
5. 训练后这个错误是否减少？

## 4. 错误类型和训练标签

除了现有的 `excellent`、`inaccuracy`、`mistake` 和 `blunder`，每个失误还应增加可解释的训练标签：

- `missed_threat`：没有发现对方直接威胁；
- `hanging_piece`：棋子无保护或被白吃；
- `missed_capture`：漏掉有利吃子；
- `missed_mate`：漏掉将杀；
- `king_safety`：将帅安全问题；
- `poor_development`：开局出子效率低；
- `repeated_move`：重复移动同一个棋子；
- `pawn_overextension`：兵卒推进过度；
- `candidate_moves`：没有比较候选着；
- `calculation_depth`：连续计算不足；
- `time_management`：思考时间异常；
- `endgame_technique`：残局技术问题；
- `unknown`：当前证据不足，无法可靠分类。

分类由三部分协作：

1. **皮卡鱼**提供评分、最佳着和推荐变化；
2. **本地规则**识别可以确定的棋局特征和行为特征；
3. **大语言模型**只能根据给定证据从允许的标签中选择，并负责教学解释。

大语言模型不能修改皮卡鱼评分，也不能在没有证据时编造错误原因。

## 5. 阶段训练计划

AI 不应该只给出“你需要更加仔细”这种笼统建议，而应生成能够执行和检验的训练处方。

例如，最近十盘统计为：

```text
严重失误：8 次
其中漏看直接威胁：5 次
平均思考时间：2.1 秒
三次在优势局面中丢子
两次错过将杀
```

系统应生成类似计划：

```text
本阶段主要问题：
落子前没有稳定检查对方的强制手段。

未来七天训练：

1. 对方威胁识别：10 题；
2. 一步吃子与反吃判断：8 题；
3. 三步强制变化计算：5 题；
4. 寻找最快将杀：3 题。

执行要求：
每题先写出对方的将军、吃子和直接威胁，再选择走法。

检验标准：
未来五盘中，因为漏看直接威胁造成的严重失误减少到 1 次以内。
```

## 6. 习题来源和比例

训练内容应该主要来自用户自己的真实错误，而不是让语言模型随机编题：

- 70%：用户自己的历史错误局面；
- 20%：从错误局面产生的同类变式；
- 10%：用于检验迁移能力的陌生局面。

每道习题必须保存来源和生成原因：

```text
训练题：寻找红方当前最需要处理的威胁。

来源：第 50 盘，第 23 个半回合。

生成原因：用户最近十盘有四次没有发现对方车炮侵入。

训练目标：先检查对方的将军、吃子和直接威胁。
```

用户应当能够查看“为什么系统推荐这道题”。

## 7. AI 生成习题后的验证

语言模型不能直接决定题目是否正确。正确流程是：

```text
AI 提出训练主题
→ 程序选择或生成候选局面
→ 规则引擎检查局面是否合法
→ 皮卡鱼搜索最佳着和多个可接受着法
→ 确认题目具有明确训练价值
→ 才加入用户训练队列
```

训练判分不能只比较是否等于皮卡鱼第一推荐着。若学生着法与最佳着评分接近，也应接受：

| 与最佳评分差距 | 训练判定 |
| ---: | --- |
| 0～30 | 正确 |
| 31～80 | 基本正确，但存在更优选择 |
| 81～200 | 未解决主要问题 |
| 超过 200 | 错误 |
| 进入被将杀 | 严重错误 |

## 8. 分层提示

每道训练题不要立即显示答案，而应依次提供：

1. **方向提示**：例如“先检查对方是否存在直接吃子”；
2. **局部提示**：例如“注意黑方二路线上的车”；
3. **计算提示**：例如“比较炮二退一和兵三进一之后黑方的最强回应”；
4. **最终解析**：推荐走法、关键变化、原因以及用户历史上的同类错误。

系统同时记录提示使用次数。答对但高度依赖提示，与独立答对代表不同的掌握程度。

## 9. 什么是有效的用户画像

用户画像不是 AI 写的一段人物评价，而是一套不断更新、可以追溯、可以验证的数据模型。

有效画像应该回答：

1. 用户目前哪些能力较强？
2. 哪些能力较弱？
3. 弱点是偶然失误，还是稳定习惯？
4. 用户在什么类型局面中容易出错？
5. 错误发生前有什么共同特征？
6. 用户接受什么训练后进步最快？
7. 哪些问题经过训练仍然没有改善？
8. 下一阶段最值得训练什么？
9. 系统对判断有多大把握？
10. 支持结论的具体证据是什么？

## 10. 用户画像的能力维度

### 棋力维度

- 开局出子；
- 子力协调；
- 战术计算；
- 候选着选择；
- 对方威胁识别；
- 将帅安全；
- 局面判断；
- 优势转化；
- 防守能力；
- 残局能力。

### 思考习惯

- 是否检查对方将军；
- 是否检查对方吃子；
- 是否比较至少两个候选着；
- 是否过早落子；
- 是否在复杂局面投入更多时间；
- 是否在优势时放松警惕；
- 是否反复移动同一个棋子；
- 是否只考虑自己的计划。

### 学习行为

- 训练完成率；
- 训练正确率；
- 提示依赖程度；
- 同类题第二次是否答对；
- 间隔一周后是否仍然掌握；
- 训练中的进步能否迁移到真实对局；
- 用户是否执行了训练建议。

## 11. 用户画像的三层结构

### 第一层：事实

事实由数据库和引擎产生，AI 不能修改：

```text
最近十盘完成 186 个红方走法
平均局面损失 64.2
严重失误 7 次
其中 5 次发生在思考时间少于 3 秒时
3 次没有处理对方直接吃子
2 次错过强制将杀
“威胁识别”训练完成 12 题，正确 8 题
```

### 第二层：诊断假设

AI 根据事实提出可验证的解释：

```text
可能问题：
用户在复杂局面中仍然过快落子，没有形成固定的威胁检查流程。

置信度：0.76

依据：
最近十盘的 7 次严重失误中，有 5 次思考时间低于 3 秒，
其中 3 次遗漏对方直接攻击。
```

诊断必须标明它是“假设”，而不是不可改变的人格标签。

### 第三层：教学处方

AI 根据诊断生成训练任务和成功标准：

```text
未来七天训练：

1. 对方直接威胁识别：每天 5 题；
2. 每题必须先写出对方所有将军和吃子；
3. 完成 3 组限时三分钟计算训练；
4. 下一盘实战启用“落子前检查表”。

检验标准：
未来五盘中，因为漏看直接威胁造成的严重失误减少到 1 次以内。
```

## 12. 证据、置信度和状态

每条画像结论都必须保存证据：

```json
{
  "dimension": "threat_awareness",
  "hypothesis": "对方威胁检查不稳定",
  "confidence": 0.76,
  "status": "needs_verification",
  "evidence": [
    {
      "game_id": 50,
      "ply": 23,
      "score_loss": 228,
      "reason": "没有处理黑车侵入"
    },
    {
      "game_id": 50,
      "ply": 31,
      "score_loss": 300,
      "reason": "没有发现强制将杀"
    }
  ],
  "recommended_training": "direct_threat_check",
  "next_evaluation_after_games": 5
}
```

一次失误不能形成稳定结论。建议使用以下状态：

| 证据情况 | 画像状态 |
| --- | --- |
| 只出现一次 | 偶发现象 |
| 不同对局出现两次 | 待验证问题 |
| 最近五盘出现三次以上 | 较稳定弱点 |
| 训练后明显减少 | 正在改善 |
| 间隔复习和实战均稳定 | 基本掌握 |
| 训练后仍反复出现 | 顽固问题 |

## 13. 保存画像随时间的变化

画像不能只保存当前值，还要保存历史快照：

```text
日期          威胁识别    候选着比较    时间管理
8 月 1 日       38           45           32
8 月 15 日      51           48           46
9 月 1 日       67           61           63
```

这样才能判断：

- 用户是否真的进步；
- 哪种训练最有效；
- 哪些能力停滞；
- 是否出现遗忘；
- 最近状态下降，还是长期能力不足。

## 14. 训练效果是画像的重要组成部分

画像不能只记录问题，还必须记录教学干预的效果：

```text
问题：漏看对方直接威胁。

训练：完成 20 道威胁识别题。

训练前：最近五盘出现 6 次相关失误。

训练后：最近五盘出现 2 次相关失误。

结论：训练可能有效，继续保持间隔复习。
```

长期积累后，系统可以发现某名用户更适合哪种训练方式，例如：

- 静态选择题效果不明显；
- 使用自己的历史错局效果更好；
- 分层提示比直接显示答案效果更好；
- 每天短时训练比每周集中训练更稳定。

这才是真正意义上的个性化。

## 15. AI 每次读取什么数据

随着数据增加，不能每次把整个数据库发送给模型。本地程序应先生成结构化摘要：

```text
长期画像
+ 最近十盘趋势
+ 当前重点能力
+ 最近训练效果
+ 3～5 条最相关证据
+ 用户当前目标
```

输入示例：

```json
{
  "goal": "减少严重失误",
  "recent_games": 10,
  "profile": {
    "threat_awareness": {
      "score": 42,
      "confidence": 0.81,
      "trend": "improving"
    },
    "candidate_moves": {
      "score": 48,
      "confidence": 0.67,
      "trend": "stable"
    }
  },
  "recent_evidence": [],
  "previous_interventions": [],
  "training_response": {}
}
```

AI 必须返回结构化结果：

```json
{
  "hypotheses": [],
  "evidence_ids": [],
  "priority_dimension": "",
  "training_plan": [],
  "success_metric": "",
  "review_after_games": 5
}
```

## 16. AI 与其他组件的职责边界

| 角色 | 职责 |
| --- | --- |
| 皮卡鱼 | 棋局计算、最佳着搜索和答案验证 |
| 本地程序 | 统计、趋势、数据隔离和证据管理 |
| 大语言模型 | 发现模式、解释证据、提出诊断假设和训练计划 |
| 用户 | 提供目标、完成训练并反馈体验 |
| 教师或教练 | 审核重要诊断和教学策略 |

AI 的潜在优势包括：

- 记住每名用户数百盘对局的细节；
- 持续统计跨时间变化；
- 快速检索相似错误；
- 比较不同训练方法的效果；
- 为不同水平用户调整解释方式；
- 在用户数量增加时仍能保持连续记录。

但 AI 也可能错误解释因果关系、把相关性当成原因、生成不合法题目，或者忽略用户现实中的动机和情绪。因此，AI 必须建立在可靠数据、规则验证和教师审核之上。

## 17. 推荐数据库扩展

- `diagnosis_tags`：每一步的错误类型、来源和证据；
- `profile_dimensions`：能力维度定义；
- `profile_evidence`：画像结论关联的对局证据；
- `profile_snapshots`：每个阶段的画像快照；
- `ai_hypotheses`：AI 诊断假设、置信度和审核状态；
- `training_plans`：个性化阶段训练计划；
- `training_plan_items`：计划中的具体练习；
- `generated_exercises`：生成或选择的训练题；
- `exercise_tags`：习题与能力维度的关联；
- `exercise_attempts`：答案、用时、提示使用和评分；
- `mastery_history`：各能力随时间的变化；
- `interventions`：已经实施的训练方法；
- `training_effects`：训练前后效果；
- `user_goals`：用户主动设置的目标；
- `user_feedback`：用户对建议和训练的反馈。

## 18. 第一阶段实现顺序

1. 给历史失误增加错误标签；
2. 为画像结论建立证据和置信度；
3. 每十盘生成一份结构化训练计划；
4. 自动选择 10 个历史错误局面组成训练包；
5. 让 AI 为每题生成三级提示和复盘问题；
6. 使用皮卡鱼动态判分，而不是只比较第一推荐着；
7. 根据训练结果安排间隔复习；
8. 在个人画像中显示不同错误是否随训练减少；
9. 比较训练前后的真实对局表现；
10. 根据效果修正下一阶段计划。

## 19. 从象棋迁移到数学教育

| 象棋训练 | 数学学习 |
| --- | --- |
| 一步棋 | 一道题或一个解题步骤 |
| 皮卡鱼评分 | 标准答案、评分点和数学工具 |
| 战术错误标签 | 知识点与错因标签 |
| 错误局面训练 | 个性化错题和变式题 |
| 棋手能力画像 | 学生知识与思维画像 |
| 多盘表现趋势 | 多次作业和考试趋势 |
| 训练后实战检验 | 后续作业与考试迁移检验 |

因此，MindDuet 最有价值的长期资产不是某一个大模型，而是：

> 一套能够保存学习证据、理解个人差异、实施教学干预并验证教学效果的长期系统。
