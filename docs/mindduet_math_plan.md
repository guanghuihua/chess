# MindDuet Math：高中数学个性化学习系统计划

## 项目定位

MindDuet 的长期目标是探索人与 AI 如何共同学习、共同判断和持续改进。

- **MindDuet Xiangqi** 是中国象棋个性化训练原型。
- **MindDuet Math** 是面向高中数学的个性化学习与教师辅助系统。

象棋项目已经验证了一条可迁移的路径：记录学习行为，使用可靠工具进行评价，让大语言模型解释原因，通过个人数据库追踪长期变化，再生成针对性训练。

## 核心原则

数学系统由四部分协作：

1. **判题器、标准答案和评分规则**负责保证基础判断准确。
2. **大语言模型**负责解释错因、启发思考和生成适当的变式训练。
3. **个人学习数据库**负责保存长期证据、更新学生画像和观察发展趋势。
4. **教师**负责设计教学目标、审核重要诊断并处理复杂或不确定的情况。

大语言模型不能独自决定学生是否掌握某个知识点，也不能根据一次错误给学生贴标签。所有重要诊断都应能够追溯到具体作答证据，并允许教师修正。

## 学习闭环

```text
学生作答
→ 答案与步骤判定
→ 知识点和错因诊断
→ 更新个人画像
→ 生成针对性训练
→ 延迟复习与再次检测
→ 生成学生报告和教师报告
```

## 第一版的范围

第一版不覆盖整个高中数学，只选择一个正在教学的小专题。候选专题包括：

- 函数的单调性与最值
- 基本不等式
- 数列通项与求和
- 三角函数的图像与性质
- 立体几何中的线面关系

推荐先以“函数的单调性与最值”为试点，建立约 10～15 个知识点、50～100 道教师审核题目和 5～10 种常见错误类型，并邀请少量学生试用。

## 最小可行产品（MVP）

第一版需要完成以下完整场景：

> 一名学生完成 10 道同一专题的题目。系统记录答案、步骤、用时、信心和提示使用情况，判断涉及的知识点和可能错因，生成 5 道针对性训练题。训练完成后，系统显示掌握度变化，并分别生成学生报告和教师报告。

MVP 功能：

1. 创建、切换学生账号，每名学生数据相互独立。
2. 显示题目并记录最终答案、解题步骤、用时、自评信心、提示次数和修改次数。
3. 对客观题直接判定；使用符号计算检查代数式等价性；对解答题按照评分规则分析。
4. 标记概念错误、运算错误、审题错误、分类讨论不完整、推理条件缺失、方法选择不当和表达不规范等错因。
5. 建立知识点掌握度、错误频率、解题速度、提示依赖和信心偏差画像。
6. 根据薄弱知识点和历史错误生成小型训练包，并安排间隔复习。
7. 每完成 10～20 道有效题目生成一次阶段报告，所有重要结论附带作答证据。
8. 为教师提供审核入口，允许修改 AI 诊断和训练安排。

## 第一版推荐策略

第一阶段不直接使用强化学习。先使用可以解释和调试的规则：

```text
推荐优先级 =
知识点薄弱程度
× 错误重复程度
× 知识点重要程度
× 遗忘风险
× 题目难度适配度
```

有了足够的真实数据和明确的学习效果指标之后，再研究知识追踪、项目反应理论、多臂老虎机或强化学习推荐。

## 建议记录的数据

每次作答至少记录：

- 学生、题目、知识点和作答时间
- 最终答案与解题步骤
- 正确性、得分和教师修正结果
- 总用时、每一步用时、修改次数和提示使用情况
- 学生作答前后的信心
- 错误类型、诊断证据和系统置信度
- 后续训练题及再次作答结果

推荐的核心数据表：

- `users`：用户和角色
- `student_profiles`：学生个人画像
- `knowledge_points`：知识点体系
- `questions`：题库与标准答案
- `question_knowledge`：题目和知识点关联
- `attempts`：每次作答
- `solution_steps`：解题步骤
- `diagnoses`：错因、证据和审核状态
- `training_tasks`：针对性训练任务
- `mastery_history`：掌握度变化历史
- `stage_reports`：阶段报告
- `teacher_reviews`：教师审核和修正

## 技术路线

第一版优先采用适合数学与 AI 实验的跨平台技术：

- Python 3.12
- FastAPI：后端 API
- SQLite：本地开发与小规模试验
- SQLAlchemy + Alembic：数据访问和数据库迁移
- SymPy：表达式化简、等价性判断和符号计算
- Pydantic：数据结构与 AI 输出校验
- pytest：自动化测试
- Web 前端：浏览器中使用，避免学生端安装 Qt
- DeepSeek 或其他大语言模型：受控地生成解释和训练建议

当需要多人并发和正式部署时，再把 SQLite 升级为 PostgreSQL。Qt 象棋程序继续保留，不要求数学项目也使用 Qt。

## 隐私和教学安全

- 第一版只收集完成教学目标所需的最少数据。
- API 密钥只保存在环境变量或密钥管理工具中，不能提交到 Git。
- 发送给外部模型的数据应去除姓名、学号和联系方式等直接身份信息。
- 学生能够查看自己的记录；教师能够纠正系统诊断。
- AI 生成的新题、答案和重要评价在进入正式教学前应由教师审核。
- 数据库应支持备份、导出和删除单个学生的数据。

## 开发阶段

### 阶段 0：教学设计

确定首个专题、知识点树、题目格式、评分标准和错误分类。

### 阶段 1：数据闭环

实现用户、题库、答题、判题、作答记录和教师查看功能，暂时不依赖大语言模型。

### 阶段 2：个人画像与训练

计算掌握度，生成透明可解释的训练推荐，并通过再次测试检验效果。

### 阶段 3：AI 教练

基于评分证据生成分层提示、错因解释、反思问题和教师报告；对输出进行结构化校验。

### 阶段 4：小规模教学试验

邀请少量学生使用，比较训练前后表现，记录教师修正次数和学生反馈，检验系统是否真正改善学习。
